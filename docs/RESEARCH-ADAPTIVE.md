# 非平稳 LLM 负载下的自适应调度：文献与系统分析

> 证据分级：**A** = 原文/代码可核；**B** = 二手转述（博客、综述）；**C** = 本仓推断，未验证。
> 本文只写能追到出处的结论；追不到的标 C，不冒充 A。

## 0. 结论先行

1. **空白是真的，但描述要更精确**：不是"没人做自适应调度"，而是**缺"可解释、可回归、能证明比最好静态策略更好"的自适应**。
   动态重调度（Llumnix）、分阶段负载生成（ServeGen）都已存在，缺少的是把"策略选择"本身做成受约束的在线闭环。
2. **H-MAS 的可迁移部分是"分层闭环"，不是"多智能体"**。单机调度器用一个带时间尺度的控制器就够，
   多智能体反而引入协调开销和不可证的行为（§3）。
3. **现有系统的策略面窄且部署期固定**：vLLM 只有 FCFS / priority 两种，抢占只在资源不足时被动触发（A）。
   这意味着"运行时换策略"在主流栈里是缺位的，不只是参数没调好。
4. **本仓已有实测证明"收益依赖 regime"**（§7）：抢占在 0.37 ms step 下零收益、8 ms step 下把首字 p99 从 1.01 s 压到 18.8 ms。
   这是自适应成立的必要条件，但也提醒：**没有 regime 变化时，自适应层就是纯开销**。
5. **真正的难点是评价，不是算法**。必须用"逐阶段 oracle 上界 + kill criterion"来判，
   否则自适应系统很容易"看起来一直在动，实际比最好的固定策略更差"（§5、设计文档 §8）。

## 1. 问题定义

非平稳有三个独立来源，必须分开建模，否则"漂移"只是个含糊词：

| 来源 | 观测量 | 对调度的影响 |
|---|---|---|
| 到达率漂移 | 窗口内 λ̂、队列深度 | 决定准入/拒绝与并发度 |
| 作业大小分布漂移 | prompt/output 长度 EWMA、p90 | 决定是否值得抢占、切块大小 |
| 类别混合漂移 | 交互式/批处理占比 | 决定优先级方向与饥饿风险 |

调度器每一步只能做四个决定：**准入谁、按什么顺序、是否抢占、批多大/切多碎**。
固定策略 = 这四个决定的参数在部署时定死；自适应 = 至少一个决定在运行时被重新选择。

**为什么固定策略会输**（三条都有文献或本仓实测支撑）：
- 队头阻塞：FCFS 下长 prefill 挡住短请求（vLLM 社区讨论，B；本仓 FIFO 违约 30/45，A）。
- 饥饿：一旦开启"交互式挤批处理"，没有老化机制时批处理可能被反复挤掉（理论，A；本仓已验证会生成重算代价，A）。
- 算力浪费：无望的请求硬跑到底（本仓：拒绝把它变成显式失败，省约 2% 算力，A）。

## 2. 现有系统的策略面

| 系统 | 排序/准入 | 抢占 | 运行时可变 | 证据 |
|---|---|---|---|---|
| vLLM | `--scheduling-policy {fcfs, priority}`，启动时定 | 资源不足时被动触发；支持 recompute / swap | 否 | A（issue #40004、调度说明） |
| SGLang | 连续批处理 + RadixAttention 前缀缓存 | 未核实 | 否（未见公开策略开关） | B/C |
| Sarathi-Serve | chunked-prefill + stall-free 混合批 | 不靠抢占，靠切块避免停顿 | 切块大小静态 | A（OSDI'24 原文） |
| Llumnix | **跨实例**运行时重调度（迁移在途请求） | 通过迁移实现"让位" | 是（多实例维度） | A（OSDI'24 原文） |
| DistServe | prefill/decode 分离部署 | 不适用（阶段分离） | 配置期 | A（OSDI'24 原文） |
| H-MAS | 分层闭环，长周期调整"active scheduling policy" | 未披露 | 是（声称） | A（摘要）/B（细节） |

三条对设计有直接约束的事实：
1. vLLM 的 priority 抢占只在资源不足时发生，**不是**主动的延迟保护（A）。
2. Sarathi-Serve 证明"切块 + 不 stall"能在吞吐-延迟曲线上移动工作点，但切块大小是静态参数（A）。
3. Llumnix 证明"运行时动在途请求"在系统层可行且收益巨大（尾延迟一个数量级），但它的动作空间是**迁移**，不是单实例内的策略切换（A）。

## 3. H-MAS：能借鉴什么、不能照搬什么

摘要级事实（A，原文摘要）：四层结构——perception（轻量请求属性与成本信号）、feedback、hierarchical control、
execution；在更长的时间尺度上调整"active scheduling policy"；声称相对 SGLang 与 vLLM 有 1.2–3.0× goodput，
场景是**多租户** LLM serving。

批判：
- **多智能体不是必要条件**（C）。单机调度器的动作空间是离散 profile + 少量阈值，一个控制器即可；
  引入多个 agent 需要定义它们之间的协调协议，收益不明，失败模式反而更难归因。
- **1.2–3× 不能直接外推**（C）：多租户、不同硬件、不同基线版本；本文没有复现，也没有核实是否有公开实现。
- **摘要没说的才是关键**：切换频率、稳定性（是否振荡）、切换的代价、对照的 oracle 是什么。这些决定它到底是不是"真自适应"。

可以安全借鉴的两点：
1. **分层闭环**：快环执行、慢环决策，两层之间用明确的观测量与预算约束连接。
2. **把"策略"当一等对象**：策略是可命名、可审计、可回滚的 profile，而不是散落的 if。

## 4. 非平稳是常态：负载证据

- **BurstGPT**（A）：213 天 Azure GPT 服务真实 trace，明确强调突发与非平稳；公开数据集与代码。
- **ServeGen**（A）：全球云推理服务的负载刻画与生成，覆盖语言/多模态/推理，给出分阶段（phase）的生成方法。
  对我们的直接用途：**把"阶段化轨迹"作为评估的默认单位**，而不是一条平稳泊松流。

结论：评估协议必须包含"阶段切换"，否则自适应层没有可展示的收益；同时必须包含"平稳阶段"，用来惩罚无谓切换。

## 5. 可用的理论工具（以及它们的边界）

| 工具 | 能解决 | 边界 / 坑 |
|---|---|---|
| 老化（aging / MLFQ 思想） | 防饥饿，简单可证 | 会牺牲短作业的优先级，需要与 SLO 对齐 |
| Gittins index / cμ 规则 | 已知分布下按"期望收益/耗时"排序最优 | 分布未知或非平稳时必须在线重估，最优性不再成立 |
| 非平稳 bandit（discounted UCB / EXP3） | 在离散 profile 间做在线选择，能跟踪漂移 | 奖励延迟、噪声大；窗口必须长于一次请求的完成时间 |
| 控制论（AIMD、滞回、预算） | 防振荡、限制探索代价 | 需要人工设定预算；对突变响应慢 |
| RL（每请求决策） | 理论动作空间最大 | 样本需求大、不可解释、门禁难写；本仓模拟器是确定性的，容易过拟合 |

**选择判断**：先用"老化 + 非平稳 bandit + 安全层"覆盖 80% 的场景；
RL 只在有真实回放数据、且离散 profile 的天花板被证明不够时再考虑（C，设计取舍）。

## 6. 三级自适应与我们的切入点

| 级别 | 动作 | 实现成本 | 风险 | 适合谁 |
|---|---|---|---|---|
| L1 阈值自适应 | 调抢占开关、切块大小、批目标 | 低 | 低（可回退） | 所有系统 |
| L2 profile 选择 | 在若干经审计的策略组合间切换 | 中 | 中（需要稳定性证明） | 本仓 v0 |
| L3 每请求学习 | RL/学习型排序器 | 高 | 高（不可解释、易过拟合） | 有大规模回放数据后 |

本仓的切入点是 **L2**，理由：动作可枚举、每个 profile 都能单独回归、失败可回滚；
同时保留 L1 的阈值作为 profile 内部参数，不把两者混在一个大动作空间里。

## 7. 本仓已有的、与"自适应"直接相关的实测

（全部来自 `D:\KF\lacbs`，合成成本模型；口径见 `docs/SCHEDULER.md`）

| 实验 | 固定策略 A | 固定策略 B | 结论 |
|---|---|---|---|
| bursty，异质 SLO | FIFO：交互式违约 30/45 | EDF：11/45 | 排序本身就有大收益（A） |
| 同上，去掉切块 | EDF+切块：11/45 | EDF 不切块：11/45 | 切块在该 regime 无贡献（A） |
| flood，step 0.37 ms | 无抢占：p99 1.01 s | 抢占：无变化 | **该 regime 下抢占零收益**（A） |
| flood，step 8 ms | 无抢占：p99 1.01 s | 抢占：18.8 ms | 同策略、不同 regime，结论反转（A） |
| bursty，过载 | 不拒绝：11 次超时 | 拒绝：0 次超时（11 次显式失败） | 拒绝不提升 goodput，只省算力（A） |

这张表是自适应命题的**必要证据**：同一组策略在不同 regime 下排名会翻转。
但它同时给出警告：**如果线上 regime 很少切换，自适应层的收益约等于零，成本却是实打实的**。
