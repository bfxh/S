# M1 结果：逐阶段 oracle 与最好固定策略的差距

> 判据来源：`docs/ADAPTIVE-DESIGN.md` §8 的 kill criterion 1——
> **最好单一固定 profile 距逐阶段 oracle < 3% ⇒ 不建自适应控制器**。
> 本文件是这条判据的第一次实测结果。

## 设置

- 成本模型：`decode_us_per_seq=500`（一步约 8 ms）、16 槽位、每步 2048 token 预算。
  为什么只跑这一档：0.37 ms 档下所有 profile 都被容量淹没，测不出差别（见 `docs/SCHEDULER.md`）。
- 判定：`met_both` = 首字与 TPOT 两项都达标。TPOT 同时约束**均值**与**相邻 token 最大间隔**
  （最大间隔 ≤ 2×SLO），否则抢占造成的停顿会被平均值稀释。
- 轨迹（阶段化、确定性）：`calm-burst-calm`、`short-long`、`class-shift`、`preempt-tradeoff`、`oscillating`。
  负载按"当前配置的稳态容量"归一化（1.0 = 满负荷）。
- profile：P0 FIFO / P1 EDF / P2 EDF+抢占 / P3 +拒绝 / P4 +老化。
- oracle 的定义：**在同一条完整轨迹上**，按请求到达阶段归属达标数，逐阶段取最优 profile，
  再把各阶段最优相加。它是"提前知道每个阶段最优策略"的上界。
- 尺子自检：`lacbs-core::metrics::oracle_gap` 有单测，合成矩阵 `[[10,0],[0,10]]` 必须报 50% gap——
  否则"gap=0"可能只是尺子坏了。

## 结果（达标数 met，越高越好）

| 轨迹 | P0 | P1 | P2 | P3 | P4 | 最好固定 | oracle | gap |
|---|---|---|---|---|---|---|---|---|
| calm-burst-calm | 344 | 350 | 355 | 429 | 429 | P4 | 429 | **0.0%** |
| short-long | 656 | 660 | 666 | 665 | 665 | P2 | 666 | **0.0%** |
| class-shift | 583 | 582 | 601 | 602 | 602 | P4 | 602 | **0.0%** |
| preempt-tradeoff | 114 | 113 | 136 | 271 | 271 | P4 | 271 | **0.0%** |
| oscillating | 472 | 480 | 508 | 617 | 617 | P4 | 617 | **0.0%** |

逐阶段最优 profile（节选）：

- `short-long`：short=P4(330)、long=P2(336) —— 阶段最优确实不同，但 P2 全程 666 恰好等于 oracle。
- `preempt-tradeoff`：两个阶段都是 P4，尽管 P2 在这里付出 215,274 个重算 token 才拿到 136 达标。
- 其余三条：P4 在所有阶段都最优。

## 结论（本轮）

1. **kill criterion 1 触发**：5 条轨迹上，最好固定 profile 与 oracle 的差距都是 0.0%。
   在这个模型里，**没有必要做自适应切换**——一个"全开"的静态 profile（P3/P4）已经吃到了所有阶段最优。
2. **profile 空间是单调的**：P3 ≥ P2 ≥ P1 ≈ P0，P4 = P3。
   - 拒绝在该指标下是**免费**的：被拒的都是按定义已经赶不上首字的请求，拒掉只会腾出算力。
   - 老化在本组轨迹里没有改变任何结果（P4 与 P3 逐位相同）：EDF 已经按截止期排序，
     而最长等待（约 1 s）没有超过批处理 3×SLO 的门槛。
3. **抢占的代价可见但不改变胜负**：P2 的重算量在 8k–367k token 之间，
   在 `preempt-tradeoff` 里把批处理的 TPOT 打出违约，但换来的交互式达标仍然净赚。

## 为什么还不能据此把方向枪毙

这个 0% 是**模型内**的结论，而模型缺了三样东西，恰好是现实里让"自适应"有价值的三样：

| 缺失 | 后果 | 加入后可能反转的地方 |
|---|---|---|
| 拒绝没有客户端代价（无重试、无失败计费） | 拒绝永远单调占优 | 加了重试/退避后，拒太多会引来第二波负载 |
| 没有 KV cache 内存上限 | 抢占只花算力，不触发内存换出/颠簸 | 紧显存下，抢占的代价会远高于重算 prefix |
| 没有测量噪声与决策延迟 | 控制器可以"瞬时"看到完美信号 | 真实窗口统计有延迟，切换本身有成本 |

另外，aging 在本组轨迹里没有被真正压到触发条件，这一项机制**仍未验证**。

## 决策

- **不建自适应控制器**（M2 暂停）。
- 先做 **M1.1：补模型**——① 拒绝后按概率重试（带退避）；② KV 容量上限（驻留 token 数）；
  ③ 在轨迹里加入一段"批处理必须被保护"的强约束（批处理 TPOT 卡死在 1.2×step）。
- M1.1 复跑**同一把尺子**与同一组轨迹：
  - 若 gap 仍然 < 3% ⇒ 正式结案，保留规则表作为运维开关即可，不写学习型控制器。
  - 若 gap ≥ 5% ⇒ 再启动 M2（规则表），M3（bandit）另议。
- 在 M1.1 完成前，任何"自适应会有收益"的说法都属于未验证假设。

## 复现

```bash
cargo test -p lacbs-core          # 含 oracle 尺子自检（合成矩阵必须报 50%）
cargo run -p lacbs-sim -- --sweep # ROW 明细 + 每条轨迹的 SUMMARY
```

全量扫描约 1.6 s；同 seed 两次运行输出逐字节一致（已验证）。
