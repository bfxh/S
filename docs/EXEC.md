# 执行层 v1：内核策略跑在 tokio 任务上（含抢占）

> 目的：把模拟器里的策略（EDF 准入 / 无望即拒）落到真实异步任务上，
> 让 `tokio-console` / `dial9` / liveliness 这些工具第一次照到真实实现，而不是只照合成 harness。

## 结构

```
到达发生器（tokio task）──▶ 调度器循环（每 step_ms 一个 tick）
                              │  1. 收新请求，spawn 一个 job task（等准入）
                              │  2. 拒绝无望（now ≥ deadline）
                              │  3. 按 EDF / FIFO 排序，填满 max_seqs
                              │  4. 槽位满且等待的是交互式 → abort 一个剩余最多的批处理任务，
                              │     进度清零、记重算、冷却一个 tick 后回队
                              │  5. 给每个在跑 job 发一个 Step 许可
                              └▶ job task：收到 Admit → 做一次 prefill 计算；
                                          每收一个 Step → 做一次 decode 计算并出词
```

- 一个 tick = 一次引擎迭代；`--step-ms` 默认 8 ms。
- 槽位回收靠 job task 退出后关闭通道（`Sender::is_closed`）。
- 无望判据与内核一致：当前时刻已过首字截止期即拒绝。
- 类别混合由 `--interactive-pct` 控制（交互式：短输出、60 ms 首字；批处理：长输出、400 ms 首字）。
- 抢占 = `JoinHandle::abort()` + 进度清零 + 重新排队；首字时间跨抢占保留（已经出过首字的不再判"无望"）。

## 用法

```bash
cargo run -p lacbs-exec -- --secs 4 --tasks 256 --interactive-pct 30
cargo run -p lacbs-exec -- --secs 4 --tasks 256 --interactive-pct 30 --no-preempt   # A/B
cargo run -p lacbs-exec -- --secs 4 --tasks 256 --swap --swap-slots 8               # 换出
# 观测（另开终端）
cargo build -p lacbs-exec --features console
cargo run -p lacbs-exec --features console -- --secs 8 --tasks 192
tokio-console
```

## 实测

> **口径变化（2026-10-22）**：PR #4 把均匀到达器从"每次发完 sleep(gap)"改成"睡到绝对时刻"，
> 实际到达率小幅上升；而 256 任务 / 4 s 这个饱和微基准对到达率极敏感——同一命令的完成数
> 从 ~200 掉到 ~168（拒绝 56→88）。本页标注为历史读数的表格保留原样，但**不能与之后的重测数字直接比较**；
> 新表都注明采样数，且只在同一二进制内做横向对比。

单类别（v0 数据）：

| 场景 | 结果 |
|---|---|
| 48 任务 / 3 s（轻载） | 48 完成、0 拒绝、p99 TTFT 0.8 ms、max_running 5 |
| 256 任务 / 3 s（突发） | 247 完成、9 拒绝、246 达标、p99 119 ms（SLO 120 ms）、max_running 16、0 停滞 |
| console 探针（192 任务） | 87 个不同任务、2,552 次 poll、1,720 次 wake 被观测到 |

类别混合 + 抢占 A/B（256 任务 / 4 s，30% 交互式，三次采样的中位数）：

| 指标 | 抢占开 | 抢占关 |
|---|---|---|
| 完成 | **197** | 187 |
| 拒绝 | **59** | 69 |
| 首字达标 | **194** | 187 |
| 首字 p50 | **31 ms** | 45 ms |
| 首字 p99 | 634 ms | **393 ms** |
| 抢占次数 / 重算 token | 24 / 3,123 | 0 / 0 |

读法：抢占把交互式的达标与中位延迟拉起来，代价是**尾部翻倍**——被挤掉的批处理要重算前缀、完成得更晚。
这与模拟器里的结论一致（保护交互式、牺牲批处理尾部），但这里是墙上时间、不可逐位复现，
三次采样之间会有几个请求的抖动。

### 换出/恢复（`--swap`）：把尾部买回来

抢占时不再清零进度，而是把 KV"换出"：保留已产出 token、付固定换出代价（`--swap-us`，默认 2 ms），
换出槽位有上限（`--swap-slots`，默认 4）；槽位不够时才退回重算。

三次采样中位数（256 任务 / 4 s，30% 交互式）：

| 模式 | 完成 | 拒绝 | 首字达标 | p50 | p99 | 抢占 | 重算 token | 换出 |
|---|---|---|---|---|---|---|---|---|
| 不抢占 | 187 | 69 | 187 | 45 ms | 393 ms | 0 | 0 | 0 |
| 抢占 + 重算 | 198 | 58 | 194 | 45 ms | **671 ms** | 30 | 3,875 | 0 |
| 抢占 + 换出（4 槽） | 199 | 57 | 199 | **31 ms** | **394 ms** | 30 | 0 | 30 |
| 抢占 + 换出（8 槽） | **202** | **54** | **202** | **31 ms** | **392 ms** | 29 | 0 | 29 |

- 换出把"重算尾部"直接消掉了：p99 671 → 394 ms（−41%），重算 token 归零；
- 同时交互式的收益保留：p50 45 → 31 ms、达标 194 → 199；
- 8 槽比 4 槽再好一点（达标 199 → 202），因为更少退回重算。

2026-10-22 在现行二进制上复测（各 3 次）：重算 p99 569–615 ms、重算 token 3.1–4.0k；
换出 8 槽 p99 388–400 ms、重算 token 0、达标 174–177 vs 162–169。
**方向与幅度都复现**（绝对值因到达器口径变化不可与旧表逐格比较）。

这就是 vLLM 里 swap vs recompute 的取舍在真实 tokio 任务上的复现。

### 换出受害者怎么挑（`--victim`）

| 策略 | 含义 |
|---|---|
| `longest` | 剩余输出最多（默认） |
| `shortest` | 剩余输出最少（最快能跑完） |
| `slack` | 剩余 slack 最多（最不着急；slack = 截止期 − 预估剩余服务时间） |

**2026-10-22 校订**：本节旧读数（400 ms 档 206、200 ms 档 slack 206.5）测于 PR #4 之前的到达器。
单变量 A/B：其它代码不动、只把到达器临时改回相对节拍，completed 复现 199–205；
换回现行绝对节拍，completed 只有 168–169。饱和微基准对到达率极敏感，两代数字不可比。
下面是**现行二进制**上的 10 次采样重测（`scripts/exec_ab.py`，256 任务 / 4 s / 30% 交互式 / 换出 8 槽）：

| 批处理 SLO | victim | met（中位数 [min,max]） | p99 | 抢占（中位数 [min,max]） |
|---|---|---|---|---|
| 400 ms（默认） | longest | 172 [168, 177] | 391.5 ms | 27 [23, 30] |
| 400 ms（默认） | slack | 169 [163, 175] | 392 ms | **18.5 [14, 20]** |
| 200 ms（收紧） | longest | 172 [166, 175] | 188.5 ms | 36 [28, 41] |
| 200 ms（收紧） | slack | 174 [165, 179] | 189 ms | 29.5 [25, 36] |

结论（现行二进制，条件成立，不是普遍规律）：

- **met 上没有可分辨差异**：两档 SLO 的四组区间全部相互重叠。
  旧结论"200 ms 时 slack 的 met 区间 `[202,210]` 与 longest `[192,200]` 不重叠"**不再成立，已撤回**。
- `slack` 唯一稳定的收益是**少抢占**：400 ms 档 27 → 18.5（区间不重叠，−31%）；
  200 ms 档 36 → 29.5（区间重叠，只能算趋势）。SLO 越松，slack 对"谁最不着急"越有区分度；
  收紧到接近单请求服务时间后所有批处理都"很急"，排序退化成噪声。
- 默认仍是 `longest`（实现最简单，真实切片上更好）；需要压低换出次数时用 `slack`。
- 复跑：`py -3.11 scripts/exec_ab.py --samples 10 -- --secs 4 --tasks 256 --interactive-pct 30 --swap --swap-slots 8 --victim slack --batch-slo-us 400000`

### 混合评分（`--victim hybrid --hybrid-alpha α`）

`score = α × 归一化 slack + (1−α) × (1−完成比例)`，分数最高者先被换出——
即"越不着急、越没做多少"的批处理先让位。slack 以 400 ms 为尺度归一化，完成比例 = 已产出/目标输出。

均匀负载（256 任务/4 s，SLO 200 ms，8 次采样）：三档全部重叠——

| victim | met | p99 | 抢占 |
|---|---|---|---|
| longest | 171.5 | 190 ms | 33.5 |
| slack | 170 | 193.5 ms | 28 |
| hybrid α=0.5 | 172 | 190 ms | 36 |

真实切片（A1 最忙 60 s，SLO 200 ms，5 次采样）：

| victim | met | p99 | 抢占 |
|---|---|---|---|
| longest | 101 [100, 105] | 141 ms | 32 |
| hybrid α=0.25 | 102 [101, 102] | 130.5 ms | 30 |
| hybrid α=0.5 | 96 [95, 96] | 170 ms | 28 |
| hybrid α=0.75 | 96 [95, 99] | 143 ms | 30.5 |

- **α 越高（越看重 slack）越差**：0.5/0.75 的 met 区间与 longest 不重叠（95–99 vs 100–105）。
- α=0.25（75% 权重给完成比例）与 longest 打平（区间重叠），抢占略少；
  但没有统计上的胜出，**默认仍是 `longest`**。p99 在真实切片上的跨批抖动可达 80 ms，不作为判据。
- 结论：真实突发下"完成比例"是有用信号，"剩余 slack"作为主权重反而有害；
  混合评分保留为实验旋钮，不作为默认。

### 真实到达切片（`--arrivals-csv`）

执行层现在可以直接吃回放 CSV：`--arrivals-csv <trace.csv> --slice-start-s <s> --slice-s <s> --target-load <ρ>`，
按容量把 trace 时间缩放到墙钟，只取指定切片。

实验：ServeGen `A1_language_m-large`，取最忙的 60 秒（起 3060 s，138 条），target_load 1.0，换出 8 槽，
只动批处理 SLO（交互式固定 60 ms），每档 3 次采样（`scripts/slo_sweep.py`）。
表内是 `met [min,max] / 抢占中位数`，met = 138 条里"被服务且首字达标"的条数：

| 批处理 SLO | `longest` | `hybrid` α=0.25 | `slack` |
|---|---|---|---|
| 150 ms | 101 [100,104] / 34 | 102 [102,103] / 25 | 92 [91,93] / 25 |
| 250 ms | 100 [97,102] / 38 | 101 [101,101] / 34 | 88 [88,90] / 31 |
| 400 ms | 99 [98,99] / 39 | 99 [96,102] / 35 | 90 [86,91] / 32 |

不抢占基线（250 ms，3 次）：met 67 [66,69]，p99 235 [234,236] ms，抢占 0。

三个结论：

1. **抢占在真实突发到达上是明显正收益**：同一 250 ms 档 met 67 → 100（+49%）。
   p99 不再作为卖点：跨批抖动 162–245 ms（`longest`），与不抢占地板 235 ms 分不开；
   能稳定复现的收益是服务量，不是尾部。
2. **victim 排名不随 SLO 翻转**：`longest` 与 `hybrid` 三档都打平（区间重叠）；
   `slack` 三档都少完成 8–12 条，150/250/400 的区间与 `longest` 都不重叠。
   机制：紧 SLO 下 `slack` 退化成"抢占剩余最少者"——保住快跑完的批处理、留下占槽最久的长请求，
   切片窗口内的周转反而更慢。
3. **少抢占 ≠ 更好**：`slack`/`hybrid` 每一档的抢占次数都低于 `longest`，完成数却没有变多。
   这与均匀微基准相反——均匀负载里批处理同质，少换出没有代价；真实切片的换出换来的是槽位周转。

方法学提醒（保留）：微基准结论必须用真实到达切片复核。此前"均匀 slack 赢"的旧结论已在上一节撤回，
现在两边的共同结论是：**均匀全平、真实 `longest` 最好**。

### SLO 灵敏度：结论是否只在某个 SLO 成立

`scripts/slo_sweep.py` 固定工作负载、只改批处理 SLO。均匀到达（256 任务 / 4 s / 30% 交互式，
换出 8 槽），每格 3 次采样；表内 `met [min,max] / 抢占中位数`：

| 批处理 SLO | `longest` | `hybrid` α=0.25 | `slack` |
|---|---|---|---|
| 100 ms | 172 [172,172] / 40 | 173 [170,174] / 36 | 173 [170,179] / **25** |
| 200 ms | 173 [171,173] / 34 | 170 [169,174] / 33 | 173 [163,175] / **26** |
| 400 ms | 167 [166,171] / 25 | 171 [171,174] / 31 | 173 [171,173] / **15** |
| 800 ms | 187 [186,188] / 31 | 188 [186,190] / 26 | 186 [186,190] / 23 |

真实切片见上一节（150/250/400 ms）：`longest` ≈ `hybrid`，`slack` 每档少 8–12 条。

四条结论：

1. **均匀微基准里 met 对换出策略不敏感**：四档 SLO、三档 victim 的区间全部重叠。
   换谁不值得为 met 调参。800 ms 档 met 跳到 ~187，是因为在过载微基准里 SLO 决定"哪些等待者还值得服务"——
   放宽等于少拒一批，排空阶段多服务了约 20 条；这不是 victim 的功劳。
2. **slack 稳定少抢占**：均匀每档都最低；400 ms 档 10 次采样 27 [23,30] → 18.5 [14,20]，
   区间不重叠（−31%）；200 ms 档区间重叠，只能算趋势。SLO 越松，slack 对"谁最不着急"越有区分度。
3. **真实切片上 slack 是净损失，且不随 SLO 改善**：150/250/400 三档都少 8–12 条，区间与 `longest` 不重叠。
   "少抢占"不是通用收益——它只在批处理同质、没有周转压力时免费。
4. **放宽 SLO 不买服务量**：真实切片 `longest` 从 150→400 ms 的 met 是 101→99，抢占 34→39。
   过载（ρ=1）下排队主导；SLO 放宽只是让早期拒绝变少、批处理赖得更久，换来的抢占更多。
   这与模拟器里"只 EDF 不拒绝反而输给 FIFO"是同一条规律。

采样口径：每格 3 次，跨批抖动可达 ±4 条（共享机器，墙上时间不可逐位复现）；
**只看档间差距是否大于抖动，不读绝对值的末位**。

## 已知边界

- **抢占只支持"交互式挤批处理"一个方向**；换出是"保留进度 + 固定代价"，没有真实 KV 拷贝。
- 换出槽位耗尽时自动退回重算（vLLM 的 fallback 行为）。
- 类别只有两档，SLO 是常数；计算用 `spin` 模拟（`WORK_US=200`），不是真模型。
- 均匀模式的到达是等间隔投放，且工作负载接近饱和；真实到达用 `--arrivals-csv` 回放，但只有一条 trace。
- 墙上时间不可逐位复现（tokio 调度、Windows 定时器都有抖动）；报告的是采样中位数，次数逐处注明。
- 门的判据只有"全部交代 + 无停滞"，不涉及延迟优劣。
