# 自适应调度设计 v0：两时间尺度闭环

> 配套阅读：`docs/RESEARCH-ADAPTIVE.md`（文献与证据）、`docs/SCHEDULER.md`（现有内核与实测）。
> 本文只描述**要做什么、怎么判、什么时候停**；不含实现。

## 0. 一句话

**步级保持确定性执行（EDF + 预算抢占），窗口级在"经审计的 profile 集合"上做在线选择，
外层用安全不变量兜底**：不饥饿、不抖动、不靠拒绝刷指标、随时可回退到静态 EDF。

## 1. 目标与非目标

**目标**
1. 在阶段切换的负载上，goodput（双 SLO 达标数/秒）显著优于**任何单一固定 profile**。
2. 相对"逐阶段 oracle"的 regret 可控（目标 ≤10%）。
3. 决策可解释：每一次切换都能说出是哪个信号越界、切到了哪个 profile。
4. 任何时刻可回退：关闭控制器即得到 P1（EDF 无抢占），行为与今天一致。

**非目标（本期明确不做）**
- 每请求的 RL/学习型排序器（样本、可解释性、门禁都不成立）。
- 多智能体协作（单机不需要，见研究文档 §3）。
- 跨实例迁移（Llumnix 的维度，另一层问题）。
- 真实 GPU 后端（成本模型仍是合成的）。

## 2. 三层结构

```
L0 步循环（µs–ms）     : EDF 排序 + decode 保底 + prefill 切块 + 抢占执行   ← 已有，不改
L1 窗口控制器（秒级）   : 观测窗口统计 → 特征 → 选 profile（枚举，受约束）
L2 护栏（分钟级）      : 饥饿上界、抢占预算、拒绝上限、切换次数上限、回退开关
```

时间尺度必须分开：L0 的动作每步都发生，L1 的动作**必须**慢于一次请求的生命周期，
否则奖励信号还没形成就切走了（研究文档 §5 的坑）。

## 3. 信号（L1 的输入）

窗口 `W`（默认 2 s 模型时间，后续按真实 p99 完成时间校准）。

| 信号 | 定义 | 用途 |
|---|---|---|
| `λ̂` | 窗口内到达数的 EWMA | 压力量 |
| `prompt_mean/p90` | 窗口内到达请求的 prompt 长度分布 | 作业大小漂移 |
| `class_mix` | 交互式占比 | 优先级方向 |
| `queue_age_max` | 当前最老等待请求的等待时长 | 饥饿护栏 |
| `occupancy` | 运行槽位占用率 | 容量饱和度 |
| `rho` | `Σ(prompt_i·p_cost + output_i·d_cost) / W` 归一化到 1.0 = 满负荷 | 主压力指标 |
| `viol_rate` | 窗口内完成请求的首字/TPOT 违约率 | 质量反馈 |
| `reject_rate` | 窗口内拒绝比例 | 防奖励作弊 |
| `recompute_rate` | 窗口内因抢占重算的 token / 总 token | 抢占代价 |
| `switch_count` | 最近 60 s 内的切换次数 | 稳定性 |

**漂移检测**：对 `λ̂` 与 `prompt_mean` 各跑一个 Page-Hinkley；越界只置 `drift=true`，
不直接决定动作（动作由控制器的策略表/bandit 决定）。

## 4. Profile 空间（离散、可审计）

每个 profile 是一个完整的调度配置，**不是散落的 if**：

| id | 排序 | 切块 | 抢占 | 拒绝 | 老化 | 说明 |
|---|---|---|---|---|---|---|
| P0 | FIFO | 0 | 否 | 否 | 否 | 基线，用于对照 |
| P1 | EDF | 128 | 否 | 否 | 否 | 默认安全档 |
| P2 | EDF | 128 | 是 | 否 | 否 | 突发时保护交互式 |
| P3 | EDF | 128 | 是 | 是 | 否 | 过载时止损 |
| P4 | EDF | 128 | 是（限额） | 是 | 是 | 长尾保护，防批处理饿死 |

选择"离散 profile + 小集合"的三个理由：
1. 每个 profile 都能单独回归（已有测试覆盖 P0/P1/P2/P3 的行为）；
2. 切换的语义可解释、可回滚；
3. bandit 的样本复杂度随臂数线性增长，5 个臂在分钟级可分辨。

**新增机制只有一个：老化（P4）**。规则：等待时长超过 `max(aging_factor × 自身首字 SLO, floor)` 的请求，
在排序时被提升到队首（仍受容量约束）。它只改排序，不改抢占与拒绝，便于单独判红。

## 5. 控制器

### v0：规则表（先做，必须先跑通）

| 压力 `rho` | 漂移 | 动作 |
|---|---|---|
| < 0.6 | 否 | P1（保持；不折腾） |
| < 0.6 | 是 | P1（漂移但低载，先观察一个窗口） |
| 0.6–0.9 | 否 | P2（预先给交互式让位） |
| 0.6–0.9 | 是 | P2，且下一窗口强制评估 P3 |
| > 0.9 | 否 | P3（止损） |
| > 0.9 | 是 | P4（止损 + 防饥饿） |

规则表的价值：**它是 bandit 的对照基线**。如果规则表已经接近 oracle，就不需要学习。

### v1：非平稳 bandit（discounted UCB）

- 臂 = profile；每窗口只观测到被选中臂的奖励（标准 bandit）。
- 奖励：`reward = goodput_norm − 0.5·viol_rate − 0.3·reject_rate − 0.2·recompute_rate`。
  四项都归一化到窗口内"理想吞吐"的尺度；**拒绝必须被惩罚**，否则控制器会学会"拒光就零违约"。
- 非平稳：每窗口把历史统计乘折扣 `γ=0.95`（等效记忆约 20 个窗口）。
- 探索：前 `2×|arms|` 个窗口在低载时强制轮询；之后改为 UCB，探索率随窗口衰减。
- 冷启动：初始臂固定为 P1。

### 切换纪律（L1 与 L2 之间）

- 候选必须连续 2 个窗口优于现任超过 `margin`（默认 5%）才允许切换。
- 每分钟切换 ≤ 6 次；检测到 A→B→A 在 3 个窗口内回摆，立刻锁定现任 5 分钟。
- 任一安全不变量被触发时，规则表/bandit 的输出被覆盖（见 §6）。

## 6. 安全不变量（不可协商，优先于任何策略）

| 不变量 | 阈值 | 违反时动作 |
|---|---|---|
| 饥饿上界 | 最老等待 > 5×其首字 SLO | 强制老化提升；本窗口禁用抢占 |
| 抢占预算 | 重算 token > 窗口总量的 15% | 本窗口禁抢占（回落到 P1/P3） |
| 拒绝上限 | 窗口拒绝率 > 20% | 本窗口禁拒绝 |
| 切换上限 | 60 s 内 > 6 次 | 锁定现任 5 分钟 |
| 信号失效 | 窗口统计缺失/延迟 > 2W | 回退 P1，并标记降级 |

护栏的判据全部落在 `Report` 的现有字段上（`rejected`、`recomputed_tokens`、finished 的延迟），
不需要新的不可观测状态。

## 7. 与现有内核的接口（实现阶段的约定）

```rust
pub struct Profile {
    pub id: ProfileId,
    pub order: Policy,        // fifo | deadline
    pub chunk: u32,
    pub preempt: bool,
    pub reject: bool,
    pub aging: Option<u64>,   // None = 不老化
}

pub trait Controller {
    fn choose(&mut self, s: &Signals) -> ProfileId;
    fn observe(&mut self, w: &WindowStats);   // 奖励与代价回填
}
```

- `run()` 拆成 `run_window()` 驱动，窗口边界只影响控制器，不影响步循环语义。
- `Report` 增加按窗口的 `WindowStats`（goodput、违约、拒绝、重算、切换）。
- profile 由控制器生成 `Config` 交给现有 `sim::run`，**内核不感知控制器**（保持可单测）。

## 8. 评估协议（决定这个方向生死）

### 轨迹

四条，全部确定性、可复现：

1. `calm→burst→calm`：到达率阶跃（验证反应速度与回落）。
2. `short→long`：prompt 分布渐变（验证漂移检测）。
3. `mixed→interactive-heavy`：类别混合突变（验证优先级方向）。
4. `oscillating`：每 20 s 交替两个 regime（验证不抖动）。

每条含 3–4 个阶段，每阶段 ≥ 20 个窗口；5 个 seed。

### 对照

- 5 个固定 profile（P0–P4）各跑全程；
- **逐阶段 oracle**：每个阶段单独跑全部 profile，取该阶段最优（这是上界，不可在线达到）；
- 自适应 v0 / v1。

### 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| goodput | 双 SLO 达标请求数 / 秒 | 越高越好 |
| regret | `(oracle − adaptive) / oracle` | ≤ 10% |
| best-fixed gap | `(best_fixed − adaptive) / best_fixed` | ≤ −5%（自适应要赢） |
| 切换次数 | 全程 | ≤ 6/分钟，且无 3 窗口内回摆 |
| 最大饥饿 | 最长等待 | ≤ 5× 首字 SLO |
| 重算开销 | 重算 token 占比 | ≤ 15% |

### Kill criteria（提前写死，避免事后找补）

1. 若**最好的单一固定 profile 与逐阶段 oracle 的差距 < 3%**，说明负载的 regime 差异不足以支撑自适应 → **停**，回到静态调参。
2. 若自适应在 4 条轨迹里少于 3 条能赢 best-fixed ≥ 5% → **停**，只保留规则表作为运维开关。
3. 若 regret > 15% 或切换次数超限 → **不许上线**，先修控制器。
4. 若收益只出现在合成成本模型的某一组参数（比如仅 8 ms step）→ 标注为"条件成立"，不得泛化宣传。

## 9. 门禁（能判红的断言）

- `adaptive_beats_best_fixed`：4 条轨迹中 ≥3 条 goodput 高于所有固定 profile（主断言）。
- `no_starvation`：所有轨迹的最大等待 ≤ 5× SLO。
- `no_flapping`：切换次数 ≤ 上限，且无回摆。
- `reject_cap`：拒绝率 ≤ 20%（除非输入本来无望）。
- `fallback_is_identical`：关闭控制器时，行为与当前 P1 逐位一致（回归保护）。

变异反证（写测试时同步做）：
- 把控制器冻结成 P0 ⇒ 主断言红；
- 关闭老化 ⇒ `no_starvation` 红；
- 允许无限抢占 ⇒ `recompute` 预算断言红。

## 10. 风险与失败模式

| 风险 | 表现 | 对策 |
|---|---|---|
| 奖励作弊 | 靠拒绝或丢弃提升"分数" | 拒绝项进奖励；`reject_cap` 硬约束 |
| 观测延迟 | 切换基于过期窗口 | 窗口 ≥ p99 完成时间；信号失效即回退 |
| 振荡 | 两个 profile 来回切 | 滞回 + 回摆检测 + 锁定期 |
| 过拟合模拟器 | 只在合成成本模型上赢 | 门禁绑定多条轨迹；真实回放前不宣称 |
| 组合爆炸 | 想同时调切块/抢占/拒绝 | 只选 profile，不选连续参数 |
| 冷启动 | 前几个窗口乱切 | 固定 P1 起步 + 低载轮询 |

## 11. 里程碑与出口条件

| 里程碑 | 内容 | 状态 / 出口条件 |
|---|---|---|
| M1 | profile 抽象 + 固定 profile 扫描 + 逐阶段 oracle | **已完成**：5 条轨迹 gap 全为 0.0%（`docs/M1-ORACLE.md`） |
| M1.1 | 拒绝后重试、KV 驻留上限、可用性口径（拒绝=失败） | **已完成**：聚合 gap 1.2%–2.0%，最高单条 5.4%（`docs/M1-ORACLE.md`） |
| M2 | 规则表控制器 + 安全层 | **已实现、未通过**：6 条轨迹上 5 条劣于静态 P4、1 条打平（`docs/M2-RESULT.md`） |
| M3 | discounted UCB + 消融 | **不启动** |
| M4 | 抖动与真实定时（tokio 层） | 仅在方向重启后 |

**结论（2026-10-21 最终）**：oracle gap 确实存在（预注册批次 4/6 ≥5%），但**规则控制器抓不住它**：
6 条轨迹上 5 条劣于静态 P4（最差 −16%），1 条打平。M2 不上线，静态 P4 为默认档。
失败原因见 `docs/M2-RESULT.md`。
逐请求的"竞争门槛拒绝"（`reject_only_when_contended`，默认关）只有 3/6 改善、均值 +2.2%，
作为部署旋钮保留，不作为默认。

### 11.1 什么条件下重启

1. **真实 trace 复跑**：用 BurstGPT / ServeGen 的阶段化切片跑同一把尺，且至少 3 条轨迹的 gap ≥5%。
   **已满足**：预注册批次（固定 seed=42、配置先写死）6 条轨迹里 **4 条 ≥5%**
   （A1 9.8%、A3 5.2%、B1 7.5%、B2 17.6%），达到 ≥3 的启动线 ⇒ **M2 获授权**
   （`docs/REPLAY-TRACES.md`）。注意：缺口主要来自"拒绝与否"，且对目标函数敏感（纯达标口径只有 2/6）。
2. **目标函数包含静态档无法表达的东西**：多租户公平性、按租户区分的拒绝惩罚、成本/配额。
3. **动作空间出现真实代价差**：抢占预算、KV 感知准入、PD 分离后的两阶段调度——
   这些动作的收益/代价随阶段变化，不是"全开"能覆盖的。
4. **测量噪声与切换成本被建模**：真实窗口统计有延迟，切换本身有过渡代价；本模型都没有。

任何重启都必须先满足第 1 条，否则仍属于"用合成参数调出来的收益"。

## 12. 未决问题

1. 真实系统里换 profile 需要排空在途批次吗？需要多少个 step 的过渡期？本设计按"下一 step 生效"假设，未验证。
2. reward 的四项权重目前是拍的（0.5/0.3/0.2），需要用 M1 的数据标定，不能带进结论。
3. oracle 用的是"阶段内固定 profile"，不是"阶段内逐请求最优"；后者是更松的上界，本期不追求。
4. 若接入真实后端，成本模型要替换成实测 step 时间；届时所有阈值需要重新标定。
